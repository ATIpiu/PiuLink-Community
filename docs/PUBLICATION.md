# 源码与 Release 发布约定

PiuLink 由主工程、Android 工程和原生依赖组成。公开仓库的同一标签完整记录这些组件的源码，各平台保留自己的版本号。

## 放进源码仓库的内容

| 范围 | 对外提供的内容 |
| --- | --- |
| 主机、客户端与引擎 | 维护中的平台代码、测试、协议示例、固定上游版本、补丁、构建和安装脚本。保留安装所需的图标、清单、公开验签密钥和许可证。 |
| 公共依赖 | `packages/` 中在用的共享代码、Go 直连传输、模块锁文件和第三方声明；保留 `contracts/` 中的协议与测试数据。 |
| 自建邀请服务 | `services/rendezvous/` 的服务源码、测试与可复用的服务配置。部署说明使用示例域名或运维者自己的配置。 |
| Android | Android 源码、Gradle wrapper、原生子模块固定版本、JNI 构建输入、签名配置样例。主工程 `packages/direct-tunnel` 用于生成传输 AAR。已有的第三方二进制编译输入须核对来源和分发许可。 |
| 文档与品牌 | 项目 README、平台使用说明、构建和协议文档、许可原文、上游署名、产品所需品牌资源。文档按内容审阅，扩展名为 Markdown 本身不是排除理由。 |

历史激活服务已退出运行链路，但当前根解决方案还引用其项目和测试。复现该解决方案时保留所需源码、测试与锁文件；生产数据、售码工具和实际部署记录单独保管。混有机器路径或真实设备信息的文档先整理成可复用示例。

## 留在本机或私有维护仓库的内容

- Claude Code、Codex 等工具的工作目录、会话、权限配置、任务锁、个人指令和项目记忆。产品功能的源码即使提到 Codex、云服务或诊断，也按用途单独审阅。
- 私钥、上传密钥、签名配置实值、实际环境变量文件、激活库存、完整邀请链接、配对证书与令牌、注册表导出、真实用户数据。
- 现场排错记录、设备列表、ADB/UI 转储、截图、部署交接、安装和回滚记录；保留通用诊断工具的源码和脱敏示例。
- 本地构建目录、Gradle/SDK 缓存、工具链、下载件、模型链接及营销视频工程。商店后台资料、运营素材、旧实验与生产运维仓库单独维护。
- 开发仓库的历史与已跟踪文件需要独立审阅。`.gitignore` 只防止新增未跟踪文件；从已审核文件建立公开版本可避免连带发布旧对象、标签及内部附件。

## 放进 GitHub Release 的内容

| 附件 | 对应信息 |
| --- | --- |
| Windows Host / Client MSI、受支持的便携 ZIP | 组件版本、架构、签名状态、引擎版本和环境依赖。面向指定机器的安装与回滚套件留作本地备份。 |
| Android 通用 APK | 只选正式签名的 `PiuLink-Android-<版本>-nonRoot-universal-release.apk`。核对包名、版本号、签名证书和 Gradle 原始产物摘要。 |
| macOS ZIP、Linux TAR.GZ、iOS 源码套件 | 分别说明架构、平台、签名或实机验证情况。iOS 源码套件应标明需要自行编译。 |
| 对应源码、第三方声明、`SHA256SUMS` | 精确对应每一份分发的 GPL 二进制，提供应用修改、引擎补丁、子模块、必要的构建输入和构建脚本。GitHub 自动生成的仓库 ZIP 不展开子模块。 |

同名附件随其原标签保留。新版建立独立的版本记录。整份工作目录、现场诊断 ZIP、配置备份、签名材料和带私有邀请的启动脚本都不作为 Release 附件。附件的 SHA-256 用于核对下载内容，签名状态另行说明。
